# Level contract — what every storm-* skill shares

storm-start owns this contract. storm-big-picture, storm-process and storm-design point here for
the workspace, the re-hydration and write-back steps, the sections each level fills, how a level is
closed or reopened, and the script signatures. The conversation itself follows
`<storm-start>/references/socratic-protocol.md`.

## Paths

`<storm-start>` below is storm-start's installed directory. Claude Code substitutes
`${CLAUDE_SKILL_DIR}` only inside a SKILL.md body, never in a file read afterwards, so each SKILL.md
states the resolved value once: storm-start as `${CLAUDE_SKILL_DIR}`, a sibling skill as
`${CLAUDE_SKILL_DIR}/../storm-start`.

| What | Path |
|------|------|
| Protocol | `<storm-start>/references/socratic-protocol.md` |
| This contract | `<storm-start>/references/level-contract.md` |
| Schema (structure, enums, id prefixes) | `<storm-start>/assets/eventstorm.schema.json` |
| Template | `<storm-start>/assets/eventstorm.template.yaml` |
| Palette | `<storm-start>/assets/palette.json` |
| Worked example | `<storm-start>/assets/fixtures/biblioteca.eventstorm.yaml` |
| Scripts | `<storm-start>/scripts/render.py`, `<storm-start>/scripts/verify.py` |

## Workspace (in the user's project, not in the skill)

```
docs/domain/<slug>/
  eventstorm.yaml    # source of truth. Every storm-* skill reads it first and writes it last
  eventstorm.html    # generated by render.py. Never edited by hand
```

`<slug>` is `domain.slug`. The `session` block inside the YAML is the whole re-hydration state:
current level, the state of each level, the `stage` inside the current level (named by its level
skill), the pending questions, the next step. `session.pending_questions` has one slot per owner —
`start`, `big-picture`, `process`, `design` — and a skill writes only its own slot, so one level
never overwrites another's question. State lives in fields, never in `notes`: if a level skill needs
to remember something the schema has no field for, that is a schema change here.

## Locate the model

With a `<slug>` argument, the model is `docs/domain/<slug>/eventstorm.yaml`. Without one, glob
`docs/domain/*/eventstorm.yaml`: one match → use it; several → ask which; none → a level skill or
wrapper stops and sends the user to `/storm-start` (storm-start itself bootstraps instead).

## Re-hydrate — the first step of every storm-* skill

1. Read the located `eventstorm.yaml`.
2. Run `verify.py` on it (no `--close`). Exit 1 → show the failures and fix them with the user
   before asking anything new: a model that does not hold together is not extended.
3. Read `session`. The question in your own slot of `pending_questions` is asked FIRST, before any
   new question. Other slots are left in place; mention them if the stakeholder asks what is open.
4. Check the level precondition: every earlier level `cerrado`, OR a current decision whose `refs`
   or statement records the skip (who decided to start here, and why). When it fails, a level skill
   names the level still open, tells the user to run `/storm-start <slug>` and stops: a skip is
   decided there, never inside a level skill.
5. If your own level is `cerrado`, say so and stop: see "Reopening a level".

## Write state — the last step of every storm-* skill, including interrupted runs

1. Update `session`: `stage`, your slot of `pending_questions` (the next question, or remove it),
   `next_step`, `updated`.
2. If an authored decision was taken this run and Anamnesis is available, `inscribe` a summary (see
   Anamnesis below) and store the returned id in `session.memory_pointer`. Skip silently if it is
   not available. This goes BEFORE verify and render, because it writes to the YAML.
3. Run `verify.py`. Exit 1 → fix before leaving; never leave a broken YAML for the next run.
4. Run `render.py`.

## Repregunta limit

**2.** When the same question — or the same `FAIL` line of a level gate turned into a question —
comes back 2 times without a new answer, stop asking it. Record the gap as the protocol's "'No
sé' is an answer" says (a hotspot, plus `{desconocido: <hs-id>}` where a field needs the value),
with the severity its "Severity" section sets, and move on. This is the only place the number lives.

## What each level fills

"Fills" = the level's own sections. Every level may add to `hotspots`, `glossary`, `decisions`,
`open_questions` and `opportunities`, and must keep `speakers` and `domain.scope` current.

| Level | Fills | Stops at |
|-------|-------|----------|
| `big-picture` | `events` (past tense, `pivotal`, `failure`; no triggers required yet), `actors` (`kind`), `external_systems`, `flows` (event timelines: `kind`, `lane`, `failure_of` for a camino de falla, `walked.big-picture`, `none_said` when the voice says there is no pivot or no camino de falla) | The whole domain as a timeline of events; boundaries only as `frontera-candidata` hotspots |
| `process` | For the flujo elegido scope (below): `commands` (`actor`, `results_in`, `failure_paths`, `informed_by` only for an unknown read model), `policies` (`when` events → `then` command, `mode`, optional `delay`), `read_models` (`built_from`, `informs`), `triggered_by` on every event, `failure_mode` on a failure event whose way is unknown, `flows` extended with commands and policies, `walked.process` | Every event of the scope explained by a trigger, every command of the scope with its three failure paths resolved (an event, `no_aplica` or `desconocido`) |
| `design` | `invariants`, `aggregates` (`invariants` by id, `handles`, `emits`, `bounded_context` — or `{desconocido}` toward the open frontera), `bounded_contexts`, `glossary[].bounded_context`, `glossary[].invariants` (by id), `glossary[].validations`, the `outcome` of each frontera decision, `code_name` decisions | Aggregates, invariants, bounded contexts. NO technical decisions (storage, APIs, frameworks): those become `open_questions` with `target: praxis-design` |

**Flujo elegido.** The flows the Process level walks are the flows in `refs` of the current
`level: process` decisions — those no later decision `supersedes`. A changed choice is a new
decision with `supersedes: <the previous one>`; the old one stays as history and stops counting.
The **flujo elegido scope** is those flows plus their caminos de falla (`failure_of` one of them):
the process gates look only there, never at flows the stakeholder left out.

## Closing a level

1. Every hotspot of this level or earlier is either `resuelto` (with `resolved_by`) or open and
   `no-bloqueante`. Say to the stakeholder what stays open.
2. Run `verify.py <yaml> --close <level>`. Exit 0 is the ONLY way a level closes. Exit 1 → each
   `FAIL` line becomes the next question, under the repregunta limit.
3. Set `session.levels.<level>: {state: cerrado, closed_on: <today>}`, move `current_level` to the
   next level, set its state to `abierto` and remove `session.stage` (the next level skill sets its
   own). For `design`, leave `current_level: design`.
4. Write state (above).

## Reopening a level

A closed level is re-checked by every later `verify.py` run and is never reopened from inside a
level skill: the level skill says it is closed and sends the user to `/storm-start <slug>`. There,
reopening is a decision with authors (`speakers`, `why`, alternatives), `level` = the reopened
level; storm-start then sets its state back to `abierto`, points `current_level` at it and hands off.

## Scripts

Python 3 with PyYAML (`python3 -m pip install pyyaml`). Both exit 2 with a clear message when
PyYAML or the file is missing. On exit 2, quote the error line to the user and stop; install
PyYAML only after the user says yes. On exit 1 with an `error:` message and no `FAIL` lines, the
YAML itself is malformed: quote the error, do not run the script again until the file is fixed.

```bash
python3 <storm-start>/scripts/verify.py docs/domain/<slug>/eventstorm.yaml [--close big-picture|process|design]
python3 <storm-start>/scripts/verify.py --list
python3 <storm-start>/scripts/render.py docs/domain/<slug>/eventstorm.yaml [-o out.html]
```

| Script | Exit 0 | Exit 1 | Exit 2 |
|--------|--------|--------|--------|
| `verify.py` | every check passes | at least one check failed (the report lists `FAIL <check>` lines with ids), or the YAML is malformed (an `error:` message, no report) | usage, IO, missing PyYAML, or a schema keyword outside the supported subset |
| `render.py` | HTML written; prints its path | the YAML is malformed (an `error:` message) | usage, IO, missing PyYAML |

verify.py checks structure only. It is the only list of checks: `verify.py --list` prints each one
with when it runs, when it fails and which session fixes it, and every `FAIL` line of a report
carries that session. Do not copy the list elsewhere.

`--close <level>` exiting 0 means the level MAY close; the level skill closes it (above).

After editing a script or the schema, run verify.py on both fixtures in `<storm-start>/assets/fixtures/`:
`biblioteca.eventstorm.yaml` must exit 0, and exit 1 with `--close design` on `blocking-hotspots`
alone (`hs-libro-ejemplar`); `biblioteca.invalid.eventstorm.yaml` must exit 1 with a FAIL on every
check except `schema` and `session`. `render.py` run twice on the same file must produce
byte-identical output.

## Anamnesis (optional)

Disk is the source of truth; Anamnesis only receives a pointer and the decisions that matter. Use
`inscribe` with `project: <repo name>`, `topic_key: eventstorm/<repo name>/<slug>`, a content of
at most ten lines (level state, each new authored decision in one line, open blocking hotspots, and
the YAML path). Its place in the write-back is step 2 of "Write state".

## Consumers

- `new-bounded-context` takes the `design` level output.
- `praxis-survey` is meant to read `docs/domain/<slug>/eventstorm.yaml` when it exists. NOT wired
  yet: until its agent says so, hand the path to it explicitly.
